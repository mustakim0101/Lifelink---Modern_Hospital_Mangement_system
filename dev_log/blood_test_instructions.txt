Exact test sequence and expected outcomes
1. Create admin via POST /api/dev/create-admin. Expected: 201 and Admin role assigned.
2. Register IT worker, submit ITWorker application, approve it, and assign Cardiology department. Expected: ITWorker role assigned and department_admins row created.
3. Register patient with blood group A+. Expected: Patient role assigned and patients row created.
4. Register 4 donor accounts as base users. Expected: all users created with reusable credentials.
5. As Admin, create LifeLink Verification Blood Bank via POST /api/blood/schema/banks. Expected: blood_banks row created.
6. As Admin, upsert donor profiles for compatible/control/ineligible donors via POST /api/blood/schema/donor-profiles. Expected: donor_profiles rows created and Donor role attached.
7. As Admin, upsert A+ WholeBlood inventory=5 via POST /api/blood/schema/inventory. Expected: blood_inventory row created.
8. Confirm GET /api/blood/schema/overview, /banks, /donor-profiles, and /inventory all return 200. Expected: new bank/profile/inventory rows are visible.
9. Verify Exact Match Donor gets 403 from GET /api/donor/dashboard before POST /api/donor/enroll. Expected: donor is not usable before donor role/profile setup.
10. Call POST /api/donor/enroll for Exact Match Donor. Expected: Donor role/profile is created for the current user.
11. POST /api/donor/availability with isAvailable=true and no maxBagsPossible. Expected: 422.
12. Post valid availability for all donors. Expected: donor_availabilities rows created.
13. Post healthy health checks for exact/compatible/control donors and bad vitals for the ineligible donor. Expected: the ineligible donor flips to donor_is_eligible=false.
14. Attempt POST /api/donor/donations for the ineligible donor. Expected: 409, donation blocked.
15. As Patient, create POST /api/patient/blood-requests with A+, WholeBlood, Urgent, units=2, department=Cardiology. Expected: blood_requests row created with status=Pending.
16. As IT Worker, load GET /api/blood/matching/requests and GET /api/blood/matching/requests/{requestId}/suggestions. Expected: Exact and Compatible donors appear; Control and Ineligible donors do not.
17. As IT Worker, notify only Exact and Compatible donors via POST /api/blood/matching/requests/{requestId}/notify. Expected: 2 donor_notifications rows created.
18. As Exact Match Donor, read the notification and respond Accepted. Expected: match status becomes Accepted.
19. As Compatible Donor, read the notification and respond Declined. Expected: match status becomes Declined.
20. As Patient, reload GET /api/patient/blood-requests. Expected: accepted_donors contains only the Exact Match Donor.
21. As Exact Match Donor, POST /api/donor/donations with linkedRequestId, bankId, and healthCheckId. Expected: blood_donations row created and A+ WholeBlood inventory increases from 5 to 6.
22. Mark the request Fulfilled in SQL and retry POST /api/blood/matching/requests/{requestId}/notify. Expected: 409 because closed requests must not allow new notify actions.
